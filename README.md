# 멀티마켓 SOR 기반 주문체결 관리 시스템

## 1. 프로젝트 소개

Spring Boot와 MySQL을 활용한 주식 주문체결 시뮬레이터입니다. 선택한 종목의 KRX·NXT 모의 호가와 잔량을 비교하고, SOR(Smart Order Routing)로 주문을 배분합니다.

## 2. 개발 환경

- 백엔드 · Java 21, Spring Boot
- 데이터베이스 · MySQL 8
- 화면 · HTML, CSS, JavaScript
- 빌드 · Maven Wrapper

## 3. 주요 기능

- KRX·NXT의 양방향 3단계 모의 호가를 비교한 지정가 매수·매도와 시장별 분할 체결
- 한국시간 기준 KRX·NXT 장 운영 상태와 주문 유형 판정, 발표자용 시연 시간 설정
- 체험 계좌의 장 시간대별 운영 상태와 예상 체결 비교
- 시장가 매수·매도와 예상 체결대금 조회, 즉시 체결 가능한 수량을 제외한 잔량 자동 취소
- 주문 가능 금액·매도 가능 수량 부족 및 시장가 주문의 상대 호가 부족 거절
- 부분 체결, 미체결 지정가 주문의 가격·수량 정정과 취소, 현금·주식 예약 및 해제
- 정정 주문은 원주문 번호와 연결되고, 원주문의 체결 수량과 정정 주문으로 넘긴 수량이 주문 상세에 표시됩니다.
- 지정가·시장가 주문의 가격 우선 또는 수량 우선 SOR 선택, 같은 호가에서 두 기준과 단일시장의 체결 수량·대금 비교
- KRX·NXT의 모의 수수료를 주문 예상, SOR 배분, 현금 예약, 매수·매도 정산, 평단가와 체결내역에 반영
- 주문·체결내역과 잔액·보유 수량·평균 매입단가·평가손익 조회
- 삼성전자, SK하이닉스, 현대차, NAVER, 카카오 선택 및 종목별 호가·주문·체결 내역 조회
- 종목별 보유 수량·매도 가능 수량과 전체 평가자산, KRX·NXT의 누적 모의 체결량 표시
- 발표자 호가 관리와 자동 모의시장
- 모의계좌 발급, 체험 코드로 재접속, 계좌별 잔고·보유주식·주문 이력
- 주문창의 모의 계좌번호 확인과 계좌별 SOR 동의 기록

다섯 종목의 호가와 잔량은 시연용 모의 데이터입니다. 시연용 수수료는 **KRX 0.10%, NXT 0.05%**를 적용하고, 체결 건마다 원 미만을 버립니다. 매수 결제액은 체결금액에 수수료를 더하고, 매도 수령액은 수수료를 뺍니다. 평단가에는 매수 수수료가 포함되고, 보유 평가금액은 가장 높은 매수호가에 보유 수량을 곱해 계산합니다.

지정가 매수의 예약금은 지정가와 전량에 최대 모의 수수료를 더해 계산합니다. 부분 체결이나 잔량 취소가 발생하면 남은 수량에 맞춰 예약금을 줄입니다. 기존 DB의 주문은 접수 당시 조건으로 체결되며, 정정으로 새 주문을 접수하면 새 요율을 적용합니다. 누적 모의 체결량은 시장별로 완료된 매수·매도 수량의 합입니다.

**매수·매도**에서 접속한 계좌번호가 자동으로 입력됩니다. **SOR 동의서**에서 동의하면 현재 동의서 버전과 동의 시각이 해당 계좌에 기록됩니다. 주문 및 정정 API는 요청의 `accountNumber`를 접속 중인 계좌번호와 대조하고 현재 동의가 있는지 확인합니다. 이미 접수한 주문의 조회, 취소, 접수 당시 조건에 따른 대기 주문 체결은 계속 이용할 수 있습니다. 새 모의계좌에서는 별도로 동의합니다.

처음 실행하면 전 종목에 기본 호가가 준비됩니다. **시장관리 → 자동시장 시작**을 누르면 5초마다 전 종목의 KRX·NXT 호가와 잔량이 갱신되고, 체결 조건을 만족하는 대기 주문도 반영됩니다. **기본 예시 채우기 → 호가 반영**으로 선택한 종목의 호가를 시연에 맞출 수 있습니다.

지정가로 체결할 수 있는지는 호가와 지정가를 비교해 판단합니다. 가격 우선은 체결 가능한 호가의 수수료를 포함한 주당 결제액이 낮거나 수령액이 높은 순서로 배분합니다. 수량 우선은 더 많이 체결할 수 있는 시장부터 이용하고, 예상 체결 수량이 같으면 정산 금액을 비교합니다. 주문 정정과 대기 주문 체결에는 최초 주문의 종목과 배분 기준을 적용합니다.

시장 상태는 기본적으로 한국시간을 사용합니다. 주말과 `stock.market.closed-dates`에 등록된 날짜는 휴장으로 표시합니다. 2026년 11월 19일에는 양 시장의 수능일 변경 시간을 적용합니다. 시연 시각은 정상 거래일 시간표로 고정합니다.

단일가 호가 접수 구간은 지정가 접수·대기로 모의합니다. 미체결 지정가 주문은 주문관리 서버에서 대기하며, 체결 가능한 세션이 열리거나 호가가 바뀌면 다시 검사합니다. 취소는 장 마감 후에도 가능합니다.

## 4. 시스템 구조

웹 UI → REST 주문 API → 계좌번호·SOR 동의 확인 → 가용 자산 검사와 SOR 배분 → MySQL

체결 시 시장 잔량, 주문 상태, 체결 기록 및 계좌를 같은 트랜잭션으로 반영합니다. 체험 코드로 접속하는 계좌의 잔고, 보유주식, 미체결 주문과 예약 자산은 접속 종료나 서버 재시작 후에도 유지됩니다. 코드의 해시는 계좌와 연결해 MySQL에 저장됩니다. 업그레이드 이전에 발급돼 코드가 없는 임시 게스트 계좌는 재접속할 수 없으며, 기존 방식대로 서버 시작 시 미체결 주문이 정리됩니다.

## 5. 실행 방법

### 새 PC에서 실행

1. JDK 21을 설치하고 MySQL 서버를 시작합니다. MySQL에서 `stock` 데이터베이스를 만듭니다.

   ```sql
   CREATE DATABASE IF NOT EXISTS stock CHARACTER SET utf8mb4;
   ```

2. `src/main/resources/application.properties.example`을 같은 폴더에 `application.properties`라는 이름으로 복사합니다. `spring.datasource.url`, `spring.datasource.username`, `spring.datasource.password`를 실행 환경에 맞게 설정합니다. 최초 실행에 필요한 테이블과 모의 호가는 서버가 준비합니다.
3. 발표자 로그인 값을 고정하려면 `application.properties`에 다음 값을 추가하고 원하는 값으로 바꿉니다. 따로 지정하지 않으면 기본 아이디는 `demo`이고 임시 비밀번호는 시작 콘솔의 `Temporary SOR login password` 줄에서 확인할 수 있습니다.

   ```properties
   stock.login.username=presenter
   stock.login.password=원하는_비밀번호
   ```

4. IntelliJ에서 `pom.xml`이 들어 있는 `stock` 폴더를 엽니다. 프로젝트 SDK를 JDK 21로 선택하고 Maven 프로젝트를 동기화한 다음 `StockApplication`을 실행합니다. Windows PowerShell에서는 프로젝트 폴더에서 아래 명령으로도 실행할 수 있습니다.

   ```powershell
   .\mvnw.cmd spring-boot:run
   ```

5. 브라우저에서 [SOR Desk](http://localhost:8080/login.html)를 엽니다. **새 모의계좌 만들기**를 누르면 시작 예수금 1,000만 원이 지급됩니다. 발급 화면에서 **코드 복사 → 거래 화면 열기**를 누릅니다. 새 체험 코드는 영문·숫자 8자리입니다. 다음 접속 때 같은 코드를 입력하면 같은 계좌가 열립니다. 이전에 발급한 16자리 코드도 사용할 수 있습니다.

### 기존 프로젝트에 적용

서버를 정지한 뒤 압축 안의 `stock` 내용물을 기존 `pom.xml`이 있는 폴더에 덮어씁니다. 압축의 `src`와 `target/classes`에는 같은 버전의 소스와 빌드 결과가 들어 있습니다. 기존 DB와 `application.properties`를 사용해 다시 실행합니다. 가상종목 01과 LG에너지솔루션의 기존 보유분은 대시보드의 **이전 보유**에서 확인할 수 있습니다. **주문내역 → 이전 종목 내역**에서는 주문과 체결을 조회하고 미체결 주문을 취소할 수 있습니다.

### 기존 발표자 계좌로 접속

[발표자 접속](http://localhost:8080/presenter.html)을 열고 기존 아이디와 비밀번호로 접속합니다. 접속하면 대시보드에서 **시장관리**를 이용할 수 있습니다. 임시 비밀번호를 쓰는 경우 이번 실행의 IntelliJ 콘솔에서 `Temporary SOR login password` 줄을 확인합니다. HTTPS 공유 주소를 사용하는 경우에도 같은 주소의 `/presenter.html`에서 접속합니다.

대시보드에서 **발표자 체험 코드 발급 → 코드 발급**을 누르면 현재 사용 중인 `SIM-0000000001` 계좌의 체험 접속 코드를 받을 수 있습니다. 이 코드로 접속해 기존 잔고와 보유주식, 주문내역을 이어서 볼 수 있습니다. 코드를 다시 발급하면 이전 코드로는 새 접속을 시작할 수 없습니다.

### 체험 계좌에서 장 시간대 비교

**SOR 분석 → 장 시간대 → 결과 비교하기**에서 정상 거래일의 시각을 선택합니다. 예시 호가 또는 현재 호가로 시장별 지정가 체결, 접수 후 대기, 시장가 접수 여부와 예상 배분을 확인합니다. 예를 들어 08:15에는 NXT 지정가만 체결 가능하고, 10:30에는 두 시장의 지정가와 시장가 주문이 가능합니다. 20:01에는 두 시장의 주문 접수가 중단됩니다. 해당 시각은 예상 체결 비교에만 적용됩니다. 모의 주문에는 발표자가 **시장관리**에서 적용한 시연 시각 또는 현재 한국시간을 사용합니다.

### 발표 영상의 시연 재현

IntelliJ 실행 설정의 **Program arguments**에 `--spring.profiles.active=demo`를 넣으면 기본 DB 대신 `stock_demo`를 사용합니다. 시연 DB는 기존 연습 기록과 분리하고, 시작 시 현금 10,000,000원·보유 0주·대기 주문 0건인지 확인합니다. 이미 사용한 `stock_demo` 대신 새 시연 DB를 만들려면 실행 환경의 `STOCK_DEMO_DB_URL`에 해당 JDBC 주소를 지정합니다.

1. 발표자로 로그인하고 **매수·매도 → SOR 동의서**에서 안내를 읽은 뒤 동의합니다. **거래 종목**에서 **삼성전자**를 고르고 **시장관리 → 시연 시간 → 10:30 · 두 시장 운영**을 누릅니다. 자동시장을 정지한 상태에서 **기본 예시 채우기 → 호가 반영 · 대기 주문 체결**을 누릅니다.
2. **SOR 분석 → 기본 예시 → 결과 비교하기**에서 82,000원 지정가 매수 10주를 비교합니다. 가격 우선의 결제액은 820,255원(체결금액 819,600원과 수수료 655원)입니다. KRX에 10주를 배분하는 수량 우선의 결제액은 820,820원입니다.
3. **매수·매도 → SOR 배분 기준**에서 **가격 우선**을 선택하고 82,000원 지정가로 10주를 매수합니다. NXT의 81,900원 4주와 KRX의 82,000원 6주가 체결됩니다. 매수 수수료를 포함한 평단은 82,025.50원입니다.
4. 보유 10주를 81,850원에 지정가 매도합니다. NXT에서 4주가 체결되어 수수료 163원을 뺀 327,237원이 입금되고, 6주가 예약됩니다. **잔여 수량 취소**를 누르면 6주가 다시 매도 가능 수량으로 표시됩니다.
5. 종목을 **NAVER**로 바꾸고 시장관리에서 기본 예시를 반영합니다. 211,000원 지정가로 6주를 가격 우선 매수하면 NXT 4주와 KRX 2주가 체결됩니다. 대시보드에서 두 종목의 보유 내역과 체결량을 비교합니다.

거절 시연은 새 모의계좌에서 할 수 있습니다. 동의 전에 주문을 눌러 **동의 필요**를 확인합니다. 동의한 뒤 주문 계좌번호 끝자리를 바꿔 **계좌번호 불일치** 거절을 확인하고, **내 계좌번호로 복원**을 누른 뒤 다시 주문합니다.

이 프로젝트는 한 Spring Boot 서버와 한 MySQL DB를 기준으로 운영합니다.
